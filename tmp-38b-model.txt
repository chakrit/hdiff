## Violations

### V1 — `Observer::measure` hands every stage an observer most of them ignore

`measurement.rs:93`: `fn measure<T>(&mut self, stage, operation: impl FnOnce(&mut Self)
-> T)`. Of its nine call sites, five pass a closure that ignores the observer:
`prepared.rs:122` (`|_| ListedTree::build(files)`) in this area, and `styling.rs:36`,
`:50`, `:62` and `syntax.rs:145` in rendering. Rounds 26, 31 and 36 ruled a closure that
ignores its argument a Violation; here the cause is the API shape — one operation serves
two kinds of caller (stages that count work inside and stages that only take time) through
a parameter half of them discard. Split it so each call site says which it is (for
example `time(stage, || …)` beside `measure(stage, |observer| …)`), and keep the timing in
one place.

### V2 — `range_count` writes its start check as a `then(…).flatten()` trick

`parser/hunk.rs:197`: `Some((start, count)) => is_decimal(start).then(||
decimal_count(count)).flatten()`. Round 16 V7 ruled guards written as combinator tricks
(`.then_some(())?`) a Violation and round 17 rewrote `range_count` as a plain check;
round 30's `is_decimal` change brought the trick back in another spelling, building an
`Option<Option<usize>>` only to flatten it. Write the guard plainly (`if !is_decimal(start)
{ return None }` then `decimal_count(count)`), as `decimal_count` itself does at
`parser.rs:263-267`.

### V3 — `registered_path` builds `Error::ResolveExecutable` two ways

`actions/install_git_diff_pager.rs:119-131`: a `resolve_failed` closure builds
`Error::ResolveExecutable { path: executable.to_owned(), source }` for two calls, then a
second inline closure builds the same variant by hand for the third, differing only in
the path (`registered.clone()`). One constructor taking the path (`resolve_failed(path)`
returning the `map_err` closure, or an `Error::resolving(path)` helper) says once how a
failed resolution is reported.

### V4 — `FileBody::Unified` is undocumented beside its documented sibling

`document.rs:125-126`: `Metadata(MetadataBody)` carries a doc comment ("A Git section
without unified headers, …"); `Unified(Box<UnifiedBody>)` has none. Rounds 13, 15 and 17
ruled an item undocumented beside documented siblings a Violation (round 17's sweep rule
2).
